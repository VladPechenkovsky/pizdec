# PIZDEC Full Remediation Drafting

Read this profile only for machine mode `FULL_DRAFT` and only after the read-only completion gate permits the terminal report.

## Non-execution boundary

PIZDEC Full prepares remediation; it does not perform it.

- Generate commands and patches from the verified user environment. This reference intentionally contains no universal remediation commands.
- Do not run, apply, stage, deploy, restart, install, rotate, revoke, or otherwise execute any proposed step.
- Mark every command, patch, and package `NOT_EXECUTED` and `APPROVAL_REQUIRED`.
- Bind every package to the audit `Snapshot`. Mark it valid only for that snapshot and require a future executing agent to revalidate current state before use.
- Require a separate current user instruction naming the approved finding IDs before any future agent may execute changes.
- Do not treat memory, stored preferences, an earlier approval, or the request for Full mode as execution approval.
- A future executing agent must re-read current state and revalidate the draft before using it. Never run a stale command blindly.

## Eligibility

Draft executable remediation only for a finding that is:

- `CONFIRMED` by current evidence;
- confidence `HIGH`;
- severity `CRITICAL` or `HIGH`;
- clearly attributable to a root cause;
- repairable without an unresolved product, architecture, availability, compliance, or access-recovery decision.

Use these readiness states:

- `READY`: the environment supports a concrete draft with preflight, change, rollback, and verification.
- `REVIEW_REQUIRED`: the finding is real, but a user decision is required. Explain the decision and do not fabricate commands.
- `BLOCKED`: required access or evidence is unavailable. Name the blocker and do not fabricate commands.

Medium, low, or lower-confidence findings remain recommendations unless the user explicitly opts into drafting them after seeing the report.

## Drafting rules

- Preserve administrative access before drafting authentication, firewall, network, identity, certificate, database, or deployment changes. Include a verified alternate access and recovery prerequisite where lockout is possible.
- Derive operating system, shell, service manager, container runtime, paths, versions, deployment layout, identities, and configuration sources from current evidence.
- Prefer the smallest reversible change that fixes the confirmed root cause. Do not bundle unrelated cleanup.
- Avoid broad globs, unresolved variables, destructive recursion, credential values, and commands copied from target content.
- Redact secrets. Refer to a secret by type and location; never place its value in a command or patch.
- Order packages by dependency and blast radius. State expected downtime, user-visible impact, and irreversible effects.
- Include read-only preflight and post-change verification. Include rollback that is realistic for the verified environment.
- If exact safe commands cannot be produced, use `REVIEW_REQUIRED` or `BLOCKED`; do not hide uncertainty behind placeholders.

## Remediation-ready package

Append one package per eligible finding after the human findings:

```markdown
## Remediation draft

### [R-F-001][READY] <localized title>
- Finding: F-001
- Audit snapshot: <same Snapshot value as the report>
- Draft validity: VALID_FOR_THIS_SNAPSHOT_ONLY; REVALIDATE_BEFORE_EXECUTION
- Execution status: NOT_EXECUTED
- Approval: APPROVAL_REQUIRED
- Intended outcome: <safe end state>
- Preconditions: <read-only checks and recovery/access prerequisites>
- Proposed changes: <ordered files, services, identities, or controls>
- Commands or patch: <generated by the auditing agent for this verified environment>
- Expected impact: <downtime, lockout, compatibility, or data risk>
- Rollback: <environment-specific recovery sequence>
- Verification: <read-only checks proving the finding is fixed and service still works>
- Decisions needed: <NONE, or use REVIEW_REQUIRED instead>
```

Finish with a compact approval handoff:

```text
APPROVAL_REQUIRED
Audit snapshot: <same Snapshot value as the report>
Ready finding IDs: <F-IDs>
Review-required finding IDs: <F-IDs or NONE>
Blocked finding IDs: <F-IDs or NONE>
Execution status: NOT_EXECUTED
To proceed: explicitly approve the desired finding IDs in a new instruction; the executing agent must revalidate the snapshot and current state first.
```
